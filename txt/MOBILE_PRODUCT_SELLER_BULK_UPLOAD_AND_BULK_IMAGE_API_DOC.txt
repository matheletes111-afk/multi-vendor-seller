1. OVERVIEW & CAPABILITY STATUS
================================================================================
Does the mobile API have bulk product upload and bulk image upload support?
- PREVIOUS STATUS: No. Only the web seller dashboard supported bulk Excel/CSV
  imports and bulk image management, protected strictly with web session cookies.
  The `/mobileapi/product-seller/upload` directory was empty.
- CURRENT STATUS: YES, FULLY IMPLEMENTED AND SUPPORTED.
  Dedicated mobile endpoints have been built under `/mobileapi/product-seller/`
  with full Bearer JWT authentication, multi-variant grouping, auto-category
  matching, S3 storage with EXIF sanitization, and automated AI dimension
  enrichment.
  Additionally, existing `/api/product-seller/...` endpoints have been upgraded
  with dual authentication so mobile apps can call either path seamlessly.

PRIMARY ENDPOINTS:
  1. Bulk Image Upload:    POST   /mobileapi/product-seller/upload/bulk-images
  2. Image Gallery List:   GET    /mobileapi/product-seller/upload/bulk-images
  3. Delete Images:        DELETE /mobileapi/product-seller/upload/bulk-images
  4. Toggle Used Status:   PATCH  /mobileapi/product-seller/upload/bulk-images
  5. Download Template:    GET    /mobileapi/product-seller/product/bulk-template
  6. Bulk Product Import:  POST   /mobileapi/product-seller/product/bulk-import
  7. AI Packaging Progress: GET   /mobileapi/product-seller/product/bulk-import/progress

ALIAS COMPATIBILITY ENDPOINTS (Plural aliases also supported):
  - GET  /mobileapi/product-seller/products/bulk-template
  - POST /mobileapi/product-seller/products/bulk-import
  - GET  /mobileapi/product-seller/products/bulk-import/progress
  - POST /api/product-seller/products/bulk-import (supports Bearer JWT)
  - GET  /api/product-seller/products/bulk-template (supports Bearer JWT)
  - GET  /api/product-seller/products/bulk-import/progress (supports Bearer JWT)
  - POST /api/product-seller/upload/bulk-images (supports Bearer JWT)

FREQUENTLY ASKED QUESTIONS: EXCEL DOWNLOAD & CROSS-PLATFORM COMPATIBILITY
--------------------------------------------------------------------------------
Q1: Is the Excel template download available on Mobile?
A1: YES! The mobile API endpoint is:
    GET /mobileapi/product-seller/product/bulk-template?format=xlsx&dummy=true
    (or ?format=csv or ?format=json).
    The mobile app can download the template directly to the user's phone, open
    it with Microsoft Excel, Google Sheets, or Apple Numbers, or share it via
    WhatsApp / email.

Q2: Are the Excel templates COMMON between Web and Mobile?
A2: YES, 100% COMMON.
    - The backend uses the exact same template generator (`buildTemplateXlsx`)
      for both web and mobile.
    - Both contain the exact same 23 columns, headers, dummy rows, and instructions.
    - A template downloaded on Web can be uploaded from the Mobile App.
    - A template downloaded from the Mobile App can be uploaded on the Web.
    - Both use the same atomic database transaction, validation engine, category
      auto-matching, and AI dimensions background processor.

3.1 UPLOAD IMAGES IN BULK
--------------------------------------------------------------------------------
Uploads 1 or multiple image files to Amazon S3 (with fallback), strips EXIF
metadata for privacy/security, and registers each file into the seller's media
gallery library.

Endpoint: POST /mobileapi/product-seller/upload/bulk-images
Headers:
  Authorization: Bearer <TOKEN>
  Content-Type: multipart/form-data

Request Body (FormData):
  - `files`: File[] (multiple files)
  - OR `file`: File (single file)
  - Supported extensions: .jpg, .jpeg, .png, .webp, .gif
  - Max size per file: 10 MB

Success Response (200 OK):

5.1 UPLOAD & IMPORT SPREADSHEET
--------------------------------------------------------------------------------
Endpoint: POST /mobileapi/product-seller/product/bulk-import
(Alias:   POST /mobileapi/product-seller/products/bulk-import)
Headers:
  Authorization: Bearer <TOKEN>
  Content-Type: multipart/form-data

Request Body (FormData):
  - `file`: File (The .xlsx or .csv spreadsheet file)
  - Max file size: 8 MB
  - Max data rows: 500 rows per file

Success Response (200 OK):
{
  "success": true,
  "ok": true,
  "data": {
    "createdProducts": 10,
    "createdVariants": 25,
    "jobId": "job_cm8a91xkz..."
  },
  "createdProducts": 10,
  "createdVariants": 25,
  "jobId": "job_cm8a91xkz...",
  "message": "Successfully imported 10 product(s) with 25 variant(s)."
}

Validation Error Response (400 Bad Request):
If any rows fail validation, the entire file is rejected in an atomic transaction
so the database remains clean. Clear, actionable row-specific errors are returned:
{
  "success": false,
  "error": "Import validation failed",
  "errors": [
    "Row 3: price must be a valid number greater than 0",
    "Row 5: weight is mandatory for category Electronics",
    "Row 8: variant_details must be a valid JSON object string (e.g. {\"Color\":\"Red\"})",
    "Product 'Summer T-Shirt' (rows 12, 13): conflicting product_name for the same product group"
  ]
}

Plan Limit Exceeded Response (403 Forbidden):
{
  "success": false,
  "error": "This import would create 15 products but your plan allows 50 total (40 in use). Upgrade to add more."
}

job to enrich product variants with packaging dimensions (weight, height,

  Authorization: Bearer <TOKEN>

KEY NOTES ON SPREADSHEET RULES:
- Delivery Charges Removed / Default 0: Delivery charges are now automatically calculated platform-wide based on package dimensions (height, width, depth), destination region/zone, and product weight. The old custom per-KM delivery charge (`delivery_charge_per_km`) has been removed from the template and UI, and defaults to 0 on the backend.
- Simplified Variant Details: Instead of typing JSON with braces and quotes, sellers can simply enter natural key-value pairs like:
  `color: Black, size: Regular` or `color: Gold | size: Premium` (comma, semicolon, or pipe separated). Standard JSON like `{"color":"Black","size":"Regular"}` is also fully supported.
- Required Variant Fields: Every row MUST have `variant_name`, `price`, and `stock`.
- Images Separator: When providing multiple images in `product_variant_images`, separate them with `|` (e.g. `https://s3.../img1.jpg | https://s3.../img2.jpg`).
- Master Image: The master image of the product is automatically taken from the first image of the first variant.
- Category Weight Requirement: If an admin configured a category with `weightMandatory = true`, the `weight` column must be greater than 0, otherwise import will fail with a friendly prompt.

7. MULTI-VARIANT GROUPING & AUTO-CATEGORY LOGIC
================================================================================

1. Multi-Variant Grouping:
   - Rows in the spreadsheet that have the exact same `product_name` (case-insensitive)
     are automatically merged into a single parent `Product` record with multiple
     `ProductVariant` records.
   - Example:
     Row 2: product_name = "Nike Air Max", variant_name = "Size 9 / Blue"
     Row 3: product_name = "Nike Air Max", variant_name = "Size 10 / Red"
     -> Result: 1 Product ("Nike Air Max") with 2 child Variants.
   - All rows belonging to the same `product_name` must share the same `category`.

2. Intelligent Category Matching & Auto-Creation:
   - When processing the `category` column:
     Step A: Looks for an exact or fuzzy match among the seller's selected categories.
     Step B: If not selected by the seller, looks across all active marketplace categories.
             If found, it automatically connects that category to the seller's account.
     Step C: If no existing marketplace category matches, the system automatically
             creates a brand new active Category, links it to the seller, and sets
             the category icon/banner from the first variant image uploaded in the file!

8. SUBSCRIPTION LIMITS & ERROR HANDLING
================================================================================

1. Product Limit Enforcement:
   Before any records are inserted, the system queries the seller's active plan:
   `checkProductLimit(seller.id)`
   - If the seller's plan limit is reached (e.g. Free plan allows 50 products and
     seller already has 50), the upload is rejected with HTTP 403.
   - If the new import would cause the total to exceed the limit (e.g. 45 current +
     10 in file > 50 limit), the upload is rejected with HTTP 403 explaining the
     exact count.

2. Error Code Matrix:
| Status Code | Meaning            | Common Cause                                              |
| :---------- | :----------------- | :-------------------------------------------------------- |
| 200 OK      | Import Success     | Products and variants created, AI job triggered.          |
| 400 Bad Req | Validation Error   | Invalid spreadsheet syntax, missing required fields.      |
| 401 Unauth  | Unauthorized       | Missing or expired Bearer token.                          |
| 403 Forbid  | Forbidden          | Seller pending approval, suspended, or plan limit reached.|
| 404 Not Fnd | Not Found          | Seller profile does not exist.                            |
| 500 Server  | Internal Error     | File parsing error or database connectivity issue.        |

9.1 FLUTTER (DART) INTEGRATION

```dart
import 'dart:io';
import 'package:dio/dio.dart';

class BulkProductService {
  final Dio dio = Dio(BaseOptions(
    baseUrl: 'https://your-domain.com',
    headers: {'Accept': 'application/json'},
  ));

  // 1. Bulk Upload Images
  Future<List<String>> uploadBulkImages({
    required List<File> imageFiles,
    required String token,
  }) async {
    final formData = FormData();
    for (var file in imageFiles) {
      formData.files.add(MapEntry(
        'files',
        await MultipartFile.fromFile(file.path, filename: file.path.split('/').last),
      ));
    }

    final response = await dio.post(
      '/mobileapi/product-seller/upload/bulk-images',
      data: formData,
      options: Options(headers: {'Authorization': 'Bearer $token'}),
    );

    if (response.statusCode == 200 && response.data['success'] == true) {
      final images = response.data['data']['images'] as List;
      return images.map((img) => img['url'] as String).toList();
    }
    throw Exception(response.data['error'] ?? 'Image upload failed');
  }

  // 2. Download Template
  Future<void> downloadTemplate({
    required String savePath,
    required String token,
    String format = 'xlsx',
  }) async {
    await dio.download(
      '/mobileapi/product-seller/product/bulk-template?format=$format&dummy=true',
      savePath,
      options: Options(headers: {'Authorization': 'Bearer $token'}),
    );
  }

  // 3. Bulk Import Spreadsheet
  Future<Map<String, dynamic>> importProducts({
    required File spreadsheetFile,
    required String token,
  }) async {
    final formData = FormData.fromMap({
      'file': await MultipartFile.fromFile(
        spreadsheetFile.path,
        filename: spreadsheetFile.path.split('/').last,
      ),
    });

    final response = await dio.post(
      '/mobileapi/product-seller/product/bulk-import',
      data: formData,
      options: Options(headers: {'Authorization': 'Bearer $token'}),
    );

    if (response.statusCode == 200 && response.data['success'] == true) {
      return response.data['data']; // contains createdProducts, createdVariants, jobId
    } else {
      final errors = response.data['errors'];
      if (errors != null && errors is List) {
        throw Exception(errors.join('\n'));
      }
      throw Exception(response.data['error'] ?? 'Import failed');
    }
  }
}
```

9.2 REACT NATIVE (AXIOS / FETCH) INTEGRATION

```typescript
import axios from 'axios';

const API_BASE = 'https://your-domain.com';

// 1. Bulk Upload Images
export async function uploadBulkImages(images: Array<{ uri: string; name: string; type: string }>, token: string) {
  const formData = new FormData();
  images.forEach((img) => {
    formData.append('files', {
      uri: img.uri,
      name: img.name,
      type: img.type,
    } as any);
  });

  const res = await axios.post(`${API_BASE}/mobileapi/product-seller/upload/bulk-images`, formData, {
    headers: {
      Authorization: `Bearer ${token}`,
      'Content-Type': 'multipart/form-data',
    },
  });
  return res.data.data.images; // Array of { id, url, filename, size, ... }
}

// 2. Import Products Spreadsheet
export async function importProducts(file: { uri: string; name: string; type: string }, token: string) {
  const formData = new FormData();
  formData.append('file', {
    uri: file.uri,
    name: file.name,
    type: file.type,
  } as any);

  try {
    const res = await axios.post(`${API_BASE}/mobileapi/product-seller/product/bulk-import`, formData, {
      headers: {
        Authorization: `Bearer ${token}`,
        'Content-Type': 'multipart/form-data',
      },
    });
    return res.data.data; // { createdProducts, createdVariants, jobId }
  } catch (err: any) {
    if (err.response?.data?.errors) {
      throw new Error(err.response.data.errors.join('\n'));
    }
    throw new Error(err.response?.data?.error || 'Import failed');
  }
}
```

10. MOBILE DEVELOPER ACTION GUIDE: RECENT PRODUCT CRUD & BULK UPLOAD UPDATES
================================================================================

*** CRITICAL INTEGRATION NOTICE FOR MOBILE APPLICATION DEVELOPERS ***
This section specifies the recent architectural changes made to the Product Seller
APIs that affect both Bulk Spreadsheet Upload and Single Product CRUD (Add/Edit
Product forms). Please update your mobile screens, form controls, and API payloads
accordingly.

--------------------------------------------------------------------------------
10.1 REMOVAL OF PER-KM DELIVERY CHARGE (`deliveryChargePerKm`)
--------------------------------------------------------------------------------
1. Why this changed:
   - Previously, products had an optional `deliveryChargePerKm` field where sellers
     could enter a custom charge per kilometer.
   - CURRENT ARCHITECTURE: Customer shipping & delivery charges are now calculated
     automatically platform-wide by the server-side logistics engine using:
       a) Package Dimensions: Height, Width, Depth in CM
       b) Product Weight: in KG (mandatory for categories with weightMandatory=true)
       c) Destination Region / Zone: Customer delivery address state and region
   - Because shipping rates are now determined by weight, package dimensions, and
     destination zone, the manual per-KM delivery charge is deprecated and no longer
     needed from sellers.

2. Mobile App Action Items for UI/UX:
   - Screen: "Add New Product" (Create Form)
     -> HIDE OR REMOVE the "Delivery Charge Per KM" (`deliveryChargePerKm`) input field.
     -> Do NOT prompt the seller to enter a per-km delivery charge.
   - Screen: "Edit Product" (Update Form)
     -> HIDE OR REMOVE the `deliveryChargePerKm` input field.
   - Screen: "Product Details / Preview"
     -> Do NOT display any per-KM delivery charge badge or row.
     -> The backend returns `deliveryChargePerKm: 0` for compatibility.

3. Mobile App Action Items for API Payloads:
   - When calling `POST /mobileapi/product-seller/product` (Create):
     -> Omit `deliveryChargePerKm` entirely, or send `0`.
     -> Backend automatically defaults `deliveryChargePerKm` to `0`.
   - When calling `PUT /mobileapi/product-seller/product/:id` (Edit):
     -> Omit `deliveryChargePerKm` entirely, or send `0`.
   - When calling `POST /mobileapi/product-seller/product/bulk-import` (Bulk Import):
     -> The spreadsheet template now contains 23 columns (previously 24).
     -> Column `delivery_charge_per_km` has been removed.
     -> Backend automatically sets `deliveryChargePerKm = 0` for all imported items.
     -> If an older template containing `delivery_charge_per_km` is uploaded, the
        server safely ignores the column without throwing validation errors.

--------------------------------------------------------------------------------
10.2 AUTOMATED PLATFORM SHIPPING (WEIGHT + DIMENSIONS + ZONE ENGINE)
--------------------------------------------------------------------------------
The platform now calculates delivery costs dynamically for customers at checkout:
- Volumetric vs Dead Weight: The shipping engine compares dead weight (kg) with
  volumetric weight `(H x W x D in cm) / 5000` and charges according to the higher value.
- Regional Delivery Zones: Destination address is mapped to intra-city, intra-state,
  or inter-state zones with configured rate bands.
- Seller Advantage: Sellers no longer have to guess per-km rates; customers receive
  accurate, transparent shipping fees calculated instantly.

--------------------------------------------------------------------------------
10.3 BULK TEMPLATE UPDATE: 23 COLUMNS (PREVIOUSLY 24)

If your mobile app uses the JSON template schema endpoint:
  GET /mobileapi/product-seller/product/bulk-template?format=json

The response now contains 23 column definitions instead of 24.

------------------------------------------------------------
A. CREATE PRODUCT (Single Product Creation)
------------------------------------------------------------
Endpoint: POST /mobileapi/product-seller/product
Headers:
  Authorization: Bearer <TOKEN>
  Content-Type: application/json (or multipart/form-data)

Required Top-Level Fields:
  - `name`: string (Product title, required)
  - `categoryId`: string (UUID of approved category, required)
  - `variants`: Array of at least 1 variant object (required)

Optional Top-Level Fields:
  - `subcategoryId`: string | null (Optional subcategory UUID)
  - `brand`: string (Optional brand name)
  - `description`: string (Optional detailed description)
  - `condition`: "NEW" | "USED" (Defaults to "NEW")
  - NOTE: `deliveryChargePerKm` is NOT required (defaults to 0).

Variant Fields (Inside `variants` array):
  - `name`: string (Variant label e.g. "Size 40 / Sky Blue", required)
  - `price`: number (Original MRP / Base price, required, > 0)
  - `discount`: number (Final selling price customer pays, e.g. 999. Defaults to 0 / full price)
  - `stock`: integer (Available inventory quantity, required, >= 0)
  - `sku`: string (Optional unique inventory tracking code)
  - `hasGst`: boolean (Apply tax: true / false, defaults to true)
  - `weight`: number (Package weight in KG. MANDATORY if category has weightMandatory=true)
  - `height`: number (Package height in CM, defaults to AI fallback if omitted)
  - `width`: number (Package width in CM, defaults to AI fallback if omitted)
  - `depth`: number (Package depth in CM, defaults to AI fallback if omitted)
  - `deliveryDays`: integer (Expected delivery days, defaults to 7, min 1)
  - `returnType`: "RETURNABLE" | "NON_RETURNABLE" (Defaults to "NON_RETURNABLE")
  - `returnDays`: integer (Return window days e.g. 7 or 14, required if returnType is RETURNABLE)
  - `replacementAllowed`: boolean (Allow exchange/replacement: true / false)
  - `attributes`: Record<string, string> (e.g. { "Color": "Sky Blue", "Size": "40" })
  - `images`: string[] (Array of public S3 image URLs for this variant)

10.5 KEY FIELD RULES & VALIDATION CHECKLIST FOR MOBILE DEVELOPERS
--------------------------------------------------------------------------------

1. SELLING PRICE VS DISCOUNT CALCULATION:
   - When seller enters MRP = ₹1000 and Selling Price = ₹800:
     - `price`: 1000
     - `discount`: 800 (The client sends the intended selling price of 800).
     - The backend automatically stores `discount = 200` (1000 - 800) in database.
     - On GET responses, `sellingPrice` and `discountedPrice` are automatically returned
       as `800` so mobile screens can show:
       "MRP: ₹1000 | Selling Price: ₹800 (₹200 OFF / 20% OFF)"
   - Validation Rule: Selling price cannot exceed regular price (`sellingPrice <= price`).

2. ESTIMATED DELIVERY DAYS (`deliveryDays`):
   - Provide an input field "Estimated Delivery Time (Days)" on each variant.
   - Pre-populate with default value `7`.
   - Must be an integer >= 1 (e.g. 3, 5, 7).

3. DIMENSIONS & WEIGHT (SHIPPING ACCURACY):
   - `weight` (KG): Mandatory if category has `weightMandatory = true`.
     If mandatory and weight is missing/<=0, API returns:
     `"Variant X: weight is mandatory for category <CategoryName>"`
   - `height`, `width`, `depth` (CM): Provide number inputs on mobile. If left blank,
     the server automatically applies AI category-specific package dimensions.

4. CHECKLIST FOR MOBILE UI UPDATES:
   [X] Removed `deliveryChargePerKm` field from Add Product Screen.
   [X] Removed `deliveryChargePerKm` field from Edit Product Screen.
   [X] Added/Verified `deliveryDays` input field (defaults to 7).
   [X] Verified `price` (MRP) and `discount` (Selling Price) input fields.
   [X] Verified `weight` (kg), `height` (cm), `width` (cm), and `depth` (cm) inputs.
   [X] Updated Bulk Template column count to 23 columns (no `delivery_charge_per_km`).
   [X] Verified all uploaded product & media images are stored as high-performance `.webp` in S3.

5. AUTOMATED WEBP IMAGE CONVERSION & S3 SPEED OPTIMIZATION:
   - Applicable Endpoints:
     * Product CRUD: POST & PUT `/mobileapi/product-seller/product` (variant images)
     * Bulk Media Upload: POST `/mobileapi/product-seller/upload/bulk-images`
   - Server-Side Auto Conversion:
     * All uploaded images (JPEG, PNG, HEIC, TIFF, BMP, WebP, GIF) are automatically processed
       and converted to Google WebP format (`image/webp`) before uploading to Amazon S3.
     * The resulting public S3 URL will end with `.webp` (e.g. `https://s3.amazonaws.com/uploads/products/product-1718000-uuid.webp`).
     * In `sellerMediaImage` database records, `mimeType` is `"image/webp"` and `filename` has `.webp` extension.
   - Core Advantages:
     * 65% - 80% smaller image size compared to raw JPEG/PNG without visual quality degradation.
     * Drastically faster app catalog rendering and website browsing speed.
     * Automatic EXIF orientation rotation: Photos snapped on Android or iPhone cameras
       are rotated upright automatically before EXIF stripping (prevents sideways images).
     * Full transparency support (PNG transparent logos & product cutouts retain alpha channel).
   - Mobile Developer Recommendation:
     * Mobile apps can continue uploading standard `image/jpeg` or `image/png` FormData files —
       the server handles conversion automatically.
     * Optionally, mobile apps may also encode images into WebP before transmission to minimize
       seller cellular data usage and speed up mobile network requests.
