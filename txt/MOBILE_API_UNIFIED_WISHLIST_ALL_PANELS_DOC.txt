1. ARCHITECTURE & OVERVIEW
--------------------------------------------------------------------------------
The Meeem mobile app features a unified customer wishlist that works across all 4 
business verticals (panels):
  • Panel 1: Marketplace Products
  • Panel 2: Home & Professional Services
  • Panel 3: Hotels, Stays & Resorts
  • Panel 4: Restaurants & Food Items

Core Functionalities:
  1. Guest Offline Wishlist: Unauthenticated guests can tap the Heart icon on any 
     product, service, hotel, or food dish. Items are stored in local mobile storage 
     (AsyncStorage / MMKV / SQLite).
  2. Automatic Login Sync / Migration: When the guest registers or logs in as a 
     customer, the mobile app calls the `/sync` endpoint to transfer all local guest 
     items into the customer's cloud database in a single batch.
  3. Real-Time Badge Count in Header: Every panel header displays a live Wishlist 
     badge count reflecting the total items across all 4 verticals.
  4. Unified Endpoints: Uses a single set of REST endpoints with entity-specific IDs.

Base URLs:
  • Primary: /mobileapi/customer/wishlist
  • Aliases: /mobileapi/wishlist
  • Sync:    /mobileapi/customer/wishlist/sync (and /mobileapi/wishlist/sync)

Authentication:
  For authenticated requests, pass the customer JWT token in any of these headers:
    Authorization: Bearer <customer_jwt_token>
    x-auth-token: <customer_jwt_token>
    x-customer-token: <customer_jwt_token>
    x-user-id: <user_id>

Note: Only CUSTOMER role users and unauthenticated guests can use the wishlist. 
Sellers (Product, Service, Hotel, Restaurant) and Admin cannot use customer wishlists.

3. PANEL HEADERS & LIVE BADGE COUNT
================================================================================
Every panel header in the mobile app must display the Heart Icon + Badge Count:
  • If Logged In:
    - On App Launch or Tab Switch: Call `GET /mobileapi/customer/wishlist`
    - Read `data.count` and display on the header heart badge.
    - If `data.count === 0`, badge is hidden or shows 0.
    - When user adds/removes any item, update the badge count directly from the 
      `data.count` returned in the POST/DELETE response.
  • If Guest (Unauthenticated):
    - Read the length of the local `guest_wishlist` array.
    - Display `guestItems.length` on the header heart badge.

================================================================================
4. GUEST MODE & AUTOMATIC LOGIN TRANSFER (/sync)
================================================================================

Complete Mobile Workflow:

Step 1: Guest Browsing (No Login)
  - User browses any panel (Products, Services, Hotels, Foods).
  - User taps the Heart icon on an item.
  - The app stores it in local storage:
    Key: "guest_wishlist"
    Value: [
      { "productId": "prod_101" },
      { "serviceId": "serv_202" },
      { "hotelId": "hotel_303" },
      { "foodItemId": "food_404" }
    ]

Step 2: Customer Logs In or Registers
  - Customer completes login or registration and receives JWT auth token.
  - Mobile app checks `AsyncStorage.getItem("guest_wishlist")`.
  - If array is NOT empty:
      Call `POST /mobileapi/customer/wishlist/sync` with `{ "items": guestItems }`
      Headers: `Authorization: Bearer <customer_jwt_token>`
  - On API Success:
      1. Clear local storage: `AsyncStorage.removeItem("guest_wishlist")`
      2. Store `data.items` and `data.count` into app global state / Redux / Zustand.
      3. Update header badge count across all panels.

6. ERROR HANDLING & STATUS CODES
================================================================================

Status Code 401 (Unauthorized):
  Triggered when JWT token is missing, expired, or user is not CUSTOMER role.
  {
    "success": false,
    "error": "Unauthorized. Valid customer token required."
  }

Status Code 400 (Bad Request - Missing ID):
  Triggered when request body does not contain any entity ID.
  {
    "success": false,
    "error": "productId, serviceId, hotelId, or foodItemId is required"
  }

Status Code 400 (Bad Request - Multiple IDs):
  Triggered when request body contains more than one ID (e.g. productId AND hotelId).
  {
    "success": false,
    "error": "Cannot specify multiple target IDs in one request"
  }

Status Code 404 (Not Found):
  Triggered when the entity does not exist or has been deleted/disabled.
  {
    "success": false,
    "error": "Product not found"
  }
  (or "Service not found", "Hotel not found", "Food item not found", "Wishlist item not found")
