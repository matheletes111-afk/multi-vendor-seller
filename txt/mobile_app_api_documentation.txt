--------------------------------------------------------------------------------
1. GLOBAL HEADERS & CONTEXT
--------------------------------------------------------------------------------
All mobile requests should include the following standard HTTP headers:

Header Key              Type     Required  Description / Example
----------------------- -------- --------- -------------------------------------
Authorization           String   Optional  Bearer <jwt_token> (Required for auth)
X-User-Latitude         Float    Optional  User latitude (e.g. 25.2048)
X-User-Longitude        Float    Optional  User longitude (e.g. 55.2708)
X-Country-Code          String   Optional  ISO country code (e.g. UAE, KSA)
X-Currency              String   Optional  Currency code (e.g. AED, USD)
X-Language              String   Optional  Language code (e.g. en, ar)
X-Device-ID             String   Optional  Device UUID for guest session tracking

--------------------------------------------------------------------------------
2. STANDARD API RESPONSE WRAPPER
--------------------------------------------------------------------------------
All API endpoints follow a consistent JSON response format:

Success Response:
{
  "success": true,
  "data": { ... },
  "message": "Optional message string"
}

Error Response:
{
  "success": false,
  "error": "Detailed error description string",
  "code": "ERROR_CODE_NAME"
}

ENDPOINT 1: GET /mobileapi/v1/home/layout
--------------------------------------------------------------------------------
Status: [IMPLEMENTED]
Description: Unified Backend-For-Frontend (BFF) engine. Returns the complete ordered
section tree for the home screen in a single HTTP request for instant app startup.

WHY TO USE & BENEFITS FOR MOBILE DEVELOPERS:
1. ⚡ Instant App Launch: Eliminates 16+ separate HTTP network roundtrips on home screen startup.
   Reduces home screen load time drastically on mobile 3G/4G/5G networks.
2. 🎛️ Dynamic Backend Layout Control: The backend can re-order components, hide/show seasonal
   promotions, or switch banner layouts without requiring an app store update.
3. 💡 Flexibility: Using this endpoint is OPTIONAL. You can use this unified layout API to drive the
   entire screen dynamically, OR call individual micro endpoints section-by-section.

HTTP Method: GET
Path: /mobileapi/v1/home/layout
Authentication: Optional (Enriches personalization if Bearer token present)

Headers:
- Authorization (Optional)
- X-User-Latitude, X-User-Longitude (Optional)

Sample Request:
GET /mobileapi/v1/home/layout HTTP/1.1
Host: www.meeemsl.com
Authorization: Bearer <token>

================================================================================
MOBILE DEVELOPER GUIDE: CATEGORY CLICK & DEEP LINK INTEGRATION
================================================================================
When a user clicks on any category icon or card in the app across the 4 panels,
call the corresponding vertical listing API below passing the category parameter:

1. Product Category Click:
   - Deep Link: /products?category={category_slug}
   - Endpoint:  GET /mobileapi/v1/products?category={category_slug_or_id}

2. Service Category Click:
   - Deep Link: /services?category={category_slug}
   - Endpoint:  GET /mobileapi/v1/services?category={category_slug_or_id}

3. Food Category / Cuisine Click:
   - Deep Link: /food?category={cuisine_name}
   - Endpoint:  GET /mobileapi/v1/restaurants?category={cuisine_name}

4. Hotel City / Destination Click:
   - Deep Link: /hotels?city={city_name}
   - Endpoint:  GET /mobileapi/v1/hotels?city={city_name}
================================================================================
