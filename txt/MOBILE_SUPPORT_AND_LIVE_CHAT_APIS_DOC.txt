1. ARCHITECTURE OVERVIEW
================================================================================
The platform supports two distinct support channels:

A. IN-APP LIVE CHAT ("IN_APP"):
   - For authenticated users: Customer, Product Seller, Service Provider, Restaurant Partner, Hotel Host.
   - WhatsApp-style two-way live chat with Admin / Support Team.
   - Instant messaging with auto-refresh/polling and zero email spam (no SendGrid emails for in-app chat).
   - Real-time unread message tracking (displays "X new" badges on tickets and total unread count on tab).
   - Resolution locking: When Admin marks ticket as RESOLVED/CLOSED, chat input locks with prompt to start a new chat.

B. PUBLIC HELP DESK ("PUBLIC"):
   - For guest/unauthenticated visitors on public app screens (e.g., Contact Us, General Inquiries).
   - Email-based ticket desk with auto-acknowledgment and SendGrid email notifications.

================================================================================
2. SUPPORTED ROLES & USER TYPES
================================================================================
Valid values for `userType`:
  - "CUSTOMER"          : End-user marketplace shoppers / clients
  - "SELLER_PRODUCT"    : Physical product vendors & shops
  - "SELLER_SERVICE"    : Professional service providers & freelancers
  - "SELLER_RESTAURANT" : Restaurant partners & food outlets
  - "SELLER_HOTEL"      : Hotel hosts & accommodation providers

Valid values for ticket `status`:
  - "PENDING"     : Awaiting response from Support Team / User
  - "IN_PROGRESS" : Currently being handled by Support Agent
  - "RESOLVED"    : Issue resolved by Support (input locked)
  - "CLOSED"      : Conversation closed (input locked)

================================================================================
3. AUTHENTICATION & USER IDENTIFICATION OPTIONS
================================================================================
Mobile clients can identify the logged-in user using any of the following convenient methods:
  1. NextAuth Session Cookie (if using embedded webview or session auth)
  2. Query Parameter: ?userId=<USER_ID> or ?email=<USER_EMAIL>
  3. Custom Request Headers:
     - x-user-id: <USER_ID>
     - x-user-email: <USER_EMAIL>
  4. Request Body: { "userId": "<USER_ID>", "email": "<USER_EMAIL>" }

6. MOBILE UI/UX & POLLING BEST PRACTICES
================================================================================

1. Background Polling for Live Chat:
   - When the user is viewing the active chat screen, set up a timer to call:
     GET /api/mobile/support/in-app/:id?markRead=true every 3 to 5 seconds.
   - When new replies arrive, append them to your message list and trigger an animated scroll to the bottom.

2. WhatsApp-Style Message Rendering:
   - Initial Message: Render the initial `ticket.message` at the very top as the opening user bubble.
   - Replies: Loop through `ticket.replies` in chronological order:
     * `senderType === "USER"`  -> Render on the RIGHT side with user avatar/initials.
     * `senderType === "ADMIN"` -> Render on the LEFT side with Support headset icon / avatar.

3. Unread Badges ("X new"):
   - In ticket lists or drawer menus, render a red badge `unreadCount` when `ticket.unreadCount > 0`.
   - On the top support tab bar, render the badge using `totalUnread`.
   - When the user taps a conversation, clear the badge locally and call the mark-as-read endpoint.

4. Resolution Handling:
   - If `ticket.status === "RESOLVED"` or `ticket.status === "CLOSED"`, hide or disable the message input field.
   - Display a lock banner: "This support ticket is marked as Resolved. Start a new conversation for assistance."
   - Provide a button "Start New Support Chat" which switches to the ticket creation form.

================================================================================
7. STATUS CODES & ERROR HANDLING
================================================================================
- 200 OK                  : Successful request (tickets list, message sent, read status updated).
- 400 Bad Request         : Missing required fields (e.g. empty message, invalid email) or sending to a resolved ticket.
- 401 Unauthorized        : Missing userId or auth session.
- 404 Not Found           : Ticket does not exist or access denied.
- 500 Internal Error      : Server error (safe error message returned in JSON).
