GLOBAL REQUEST CONTEXT & HEADERS
--------------------------------------------------------------------------------
All home screen APIs support localization, currency handling, and location:

Header Key              Type     Required  Description / Example
----------------------- -------- --------- -------------------------------------
Authorization           String   Optional  Bearer <user_token> (Personalization)
X-User-Latitude         Float    Optional  User latitude (e.g. 25.2048)
X-User-Longitude        Float    Optional  User longitude (e.g. 55.2708)
X-Country-Code          String   Optional  ISO country code (e.g. UAE)
X-Currency              String   Optional  Currency code (e.g. AED, USD)
X-Language              String   Optional  Language code (e.g. en, ar)
X-Device-ID             String   Optional  Device UUID for guest fallback

POLICY NOTES:
1. Guest Users: Guests without Authorization Bearer token will NOT receive recent
   search data (returns empty list []).
2. Geolocation Fallback: If X-User-Latitude/Longitude (or lat/lng query params) are
   missing, Nearby Hotels and Food Spots fall back to returning Top-Rated items.


================================================================================
HOTEL CATEGORY ARCHITECTURE (CITY / LOCATION & PROPERTY TYPES)
================================================================================
Hotels are categorized primarily by City / Destination (`Hotel.city` field in DB):
- Primary Mobile Hotel Categories: Cities (e.g., Dubai, Abu Dhabi, Sharjah, Ras Al Khaimah).
- Secondary Property Type Categories: `HotelSeller.categories` JSON array (Resorts, Luxury, Villas, Apartments).
- Zero DB / CRUD Form Changes: Hotel sellers already provide `city` when adding a hotel in `hotel-seller/hotels/new`.

4. RECENT SEARCHES SECTION (Product / User Vertical)
--------------------------------------------------------------------------------
[4.1 GET RECENT SEARCHES]
* [STATUS]: [DONE]
* API Endpoint: GET /mobileapi/v1/user/recent-searches
* Purpose: User's recent search keywords with product previews & timestamps (returns [] for guest users).
* Query Params: `limit` (default: 50, returns all recent searches)
* Response Attributes: `search_id`, `query_text`, `searched_time_ago`, `image_url`, `price`, `discount_tag`

[4.2 CLEAR RECENT SEARCHES]
* [STATUS]: [DONE]
* API Endpoint: DELETE /mobileapi/v1/user/recent-searches
* Purpose: Clears history when user clicks "Clear all".
* Response Attributes: `success: true`, `message`
