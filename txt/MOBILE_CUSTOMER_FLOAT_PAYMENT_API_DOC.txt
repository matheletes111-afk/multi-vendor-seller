1. HIGH-LEVEL MOBILE CHECKOUT & POLLING ARCHITECTURE
================================================================================
When a customer selects "Float" (Card Payment) across any checkout section:
1. Mobile App submits the order/booking creation request with `paymentMethod: "FLOAT"`.
2. Backend creates the order in "PENDING" status with `settlementStatus: "ESCROW_HELD"`,
   generates a Float hosted checkout link via Float Gateway API, and returns:
   - `flotPaymentLink` (URL to Float hosted checkout)
   - `flotOrderId` (Merchant Order Reference ID)
3. Mobile App opens `flotPaymentLink` inside an in-app browser or Webview:
   - Customer enters their Card details (Card Number, CVV, Expiry, 3D Secure OTP).
4. Mobile App starts polling the dedicated `verify-payment` endpoint every 3–5 seconds.
5. Once payment is confirmed by webhook or active gateway query:
   - The verify endpoint returns `paymentStatus: "COMPLETED"`, `status: "CONFIRMED"`.
   - Mobile app closes Webview and displays Order Success Screen with:
     * Payment Method Badge ("FLOAT" / Card)
     * Float Order ID reference
     * Price breakup (Subtotal, Coupon Discount, Shipping, Total)
6. If the customer closes the payment modal, taps "Cancel", or the 300-second (5 min)
   timer elapses:
   - Mobile App calls `POST .../cancel-pending` to release held inventory/rooms/coupons.

2.2. PAYMENT VERIFICATION & POLLING
--------------------------------------------------------------------------------
Endpoint: GET /mobileapi/customer/orders/{id}/verify-payment
Auth    : Bearer <customer_token>
Params  : id = Order ID (UUID)

Case A - Payment Completed (Customer successfully completed card 3DS):
{
  "success": true,
  "paymentStatus": "COMPLETED",
  "status": "CONFIRMED",
  "paidAt": "2026-11-11T10:15:30.000Z",
  "paymentMethod": "FLOAT",
  "flotOrderId": "FLOT_ORD-20261111-9988_1731320000000"
}

Case B - Still Pending (Customer still typing card details):
{
  "success": false,
  "paymentStatus": "PENDING",
  "status": "PENDING",
  "requiresVerification": true
}

Case C - Payment Failed or Gateway Declined:
{
  "success": false,
  "paymentStatus": "FAILED",
  "status": "PENDING",
  "message": "Float card payment attempt was unsuccessful. You may retry or choose another payment method."
}

--------------------------------------------------------------------------------
2.3. CANCEL PENDING ORDER (MODAL CLOSE / 300s TIMEOUT)
--------------------------------------------------------------------------------
Endpoint: POST /mobileapi/customer/orders/{id}/cancel-pending
Auth    : Bearer <customer_token>
Params  : id = Order ID (UUID)

Request Body: {} (Empty JSON)

Success Response (200 OK):
{
  "success": true,
  "message": "Pending order cancelled and resources released."
}
* Note: Restores stock quantity, cancels pending escrow, and frees any applied coupon.

6. CUSTOMER PRICE BREAKDOWN & PRIVACY GUARANTEE
================================================================================
All mobile customer endpoints strictly return user-facing billing fields:
- Subtotal: Amount before discounts and delivery charges
- Coupon Code & Discount: Explicit deduction applied
- Shipping Fee & Breakup: Weight, dimension, and region shipping fees
- Total Amount: Final price charged to card
* IMPORTANT: Platform commission rates, seller commission amounts, and seller net
  payouts are strictly withheld from all customer responses to prevent internal data exposure.

================================================================================
7. ERROR HANDLING & GATEWAY STATUS CODES REFERENCE
================================================================================
- 400 Bad Request          : Invalid inputs, expired/invalid coupon, or missing parameters.
- 401 Unauthorized         : Missing or expired Bearer JWT token in Authorization header.
- 403 Forbidden            : Token belongs to another user or role.
- 404 Not Found            : Order, booking, room, or food item not found.
- 502 Bad Gateway          : Float Gateway connection timeout or external API unreachable.
- 500 Internal Server Error: Database or unhandled server exception.
