1. OVERVIEW & FOOD DISCOUNT SYSTEM IN CUSTOMER APP
================================================================================
Every food item in the customer mobile app includes native support for restaurant
discounts. Restaurant owners specify a regular price (MRP) and an offer selling price.
The system automatically calculates and returns:
- "price": The original listed MRP.
- "discount": The discount amount in currency units (price - sellingPrice).
- "sellingPrice" (and "selling_price"): The discounted price that the customer pays.

Key Customer App Guarantee:
When a customer adds dishes to their cart and completes checkout:
- The backend always recomputes and charges the server-validated selling price:
  chargedPrice = Math.max(0, food.price - (food.discount || 0))
- The customer is never overcharged, even if prices in a local cache or cart are old.
- The mobile app should refresh cart prices when entering checkout to avoid UI discrepancy.

================================================================================
2. PRICE FIELDS SPECIFICATION & UI DISPLAY RULES
================================================================================
Every food item payload returned by the customer endpoints contains the following fields:

┌─────────────────┬────────┬────────────────────────────────────────────────────────┐
│ Field Name      │ Type   │ Description & Meaning                                  │
├─────────────────┼────────┼────────────────────────────────────────────────────────┤
│ price           │ Float  │ Regular listed MRP / Menu price (e.g. 160.00)          │
│ discount        │ Float  │ Discount amount saved by customer (e.g. 30.00)         │
│ sellingPrice    │ Float  │ Effective selling price = price - discount (130.00)    │
│ selling_price   │ Float  │ Snake_case alias for sellingPrice (130.00)             │
└─────────────────┴────────┴────────────────────────────────────────────────────────┘

Mobile UI Presentation Guidelines:

Case 1: Dish HAS a Discount (discount > 0):
  1. Highlight Selling Price:
     Display sellingPrice prominently in bold, primary brand or green color: "Le 130.00".
  2. Strike-Through MRP:
     Display original listed price struck-through in muted gray: "~~Le 160.00~~".
  3. Savings Badge / Offer Pill:
     Display a pill beside the price:
     - Flat amount saved: "Save Le 30"
     - OR percentage discount: "{Math.round((discount / price) * 100)}% OFF" (e.g. "19% OFF").
  4. Cart & Checkout Subtotal:
     Always calculate item total as: (sellingPrice * quantity).

Case 2: Dish Has NO Discount (discount == 0):
  1. Regular Price Display:
     Display price normally: "Le 160.00".
  2. Do not show strike-through text or discount badges.

--------------------------------------------------------------------------------
6.1 CART DATA STRUCTURE & SUB-TOTAL CALCULATION RULES
--------------------------------------------------------------------------------
Store customer cart locally in SQLite / SharedPreferences / redux-persist:

Cart Storage Schema:
{
  "restaurantSellerId": "cm101seller999",
  "restaurantName": "Royal Spice Palace",
  "items": [
    {
      "foodItemId": "cm101food001",
      "name": "Hyderabadi Chicken Dum Biryani",
      "price": 130.00,          // MUST store sellingPrice (customer price)
      "originalPrice": 160.00,  // Struck-through price
      "discount": 30.00,
      "quantity": 2,
      "image": "https://res.cloudinary.com/demo/image/upload/v1/biryani1.webp",
      "isVeg": false
    }
  ]
}

Subtotal Math:
  subtotal = items.reduce((sum, item) => sum + (item.price * item.quantity), 0);
  Example: (130.00 * 2) = 260.00. (Customer savings = 60.00).

Multi-Vendor Restriction:
A food delivery order can only contain dishes from a SINGLE restaurant.
If a customer attempts to add a dish from Restaurant B while cart has dishes
from Restaurant A, present a dialog:
"Your basket contains items from another restaurant. Clear basket and add this item?"

4. An order number is generated in the format: F-YYYYMMDD-XXXX.
5. Confirmation emails are sent to Customer, Restaurant Seller, and Admin.

7. ERROR HANDLING & HTTP STATUS CODES
================================================================================
The API returns standard JSON error responses:
{
  "success": false,
  "error": "Descriptive error message"
}

HTTP Status Codes:
- 200 OK: Request processed successfully.
- 201 Created: Order placed or resource created successfully.
- 400 Bad Request: Missing required delivery fields, empty cart, or invalid payload.
- 401 Unauthorized: Bearer token is missing, expired, or invalid.
- 404 Not Found: Food item, restaurant seller, or order not found.
- 500 Internal Server Error: Database or internal execution failure. Show error string to user.

--- 8.2 React Native / TypeScript Food Price Component ---
```tsx
import React from 'react';
import { View, Text, StyleSheet } from 'react-native';

interface FoodItemProps {
  food: {
    price: number;
    discount?: number;
    sellingPrice?: number;
    selling_price?: number;
  };
}

export const FoodPriceDisplay: React.FC<FoodItemProps> = ({ food }) => {
  const mrp = food.price || 0;
  const discount = food.discount || 0;
  const sellingPrice =
    food.sellingPrice ??
    food.selling_price ??
    (discount > 0 ? Math.max(0, mrp - discount) : mrp);

  if (discount > 0) {
    const percentOff = mrp > 0 ? Math.round((discount / mrp) * 100) : 0;
    return (
      <View style={styles.container}>
        <Text style={styles.sellingPrice}>${sellingPrice.toFixed(2)}</Text>
        <Text style={styles.mrp}>${mrp.toFixed(2)}</Text>
        <View style={styles.badge}>
          <Text style={styles.badgeText}>{percentOff}% OFF</Text>
        </View>
      </View>
    );
  }

  return <Text style={styles.regularPrice}>${mrp.toFixed(2)}</Text>;
};

const styles = StyleSheet.create({

    alignItems: 'center',
    gap: 8,
```
