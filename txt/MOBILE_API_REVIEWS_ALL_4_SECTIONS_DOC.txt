--------------------------------------------------------------------------------
2.1 PRODUCT & SERVICE REVIEWS SUBMISSION (DELIVERED ORDERS)
--------------------------------------------------------------------------------
Customers can review Products and Services once their order item is marked as DELIVERED.
The order details API (`/mobileapi/customer/orders/:id`) returns:
  • `canReview`: true/false
  • `review`: null or existing review object

A) Submit New Product / Service Review:
   Endpoint: POST /mobileapi/customer/reviewrating
   Headers:
     Authorization: Bearer <customer_jwt_token>
     Content-Type: multipart/form-data  (or application/x-www-form-urlencoded)

   Form-Data Fields:
     • `orderItemId` (String, required): The ID of the delivered order item.
     • `rating` (Integer 1-5, required): Star rating score.
     • `comment` (String, optional): Review text up to 2000 characters.
     • `images` (File / Blob / URL, optional, max 5): Photos taken by customer.

   Response (201 Created):
   {
     "success": true,
     "message": "Review submitted successfully",
     "data": {
       "reviewId": "rev_001"
     }
   }

B) Edit / Update Existing Product / Service Review:
   Endpoint: PATCH /mobileapi/customer/reviewrating
   Headers:
     Authorization: Bearer <customer_jwt_token>
     Content-Type: multipart/form-data

   Form-Data Fields:
     • `orderItemId` (String, required)
     • `rating` (Integer 1-5, required)
     • `comment` (String, optional)
     • `images` (File / Blob / URL, optional, max 5)

   Response (200 OK):
   {
     "success": true,
     "message": "Review updated successfully",
     "data": {
       "reviewId": "rev_001"
     }
   }

5. STATUS CODES, VALIDATION & ERROR HANDLING
================================================================================

Common HTTP Status Codes:
  • 200 OK: Request succeeded and payload returned.
  • 201 Created: Review created successfully.
  • 400 Bad Request:
      - Missing required fields (orderItemId, rating, etc.)
      - Rating is not an integer between 1 and 5.
      - Item is not yet delivered / booked.
  • 401 Unauthorized: Missing or invalid JWT token.
  • 403 Forbidden:
      - User role mismatch (e.g. non-seller calling seller endpoint).
      - Seller plan does not allow receiving reviews.
  • 404 Not Found: Entity (Product, Service, Hotel, Food, or Review) does not exist.
  • 409 Conflict: Review already submitted for this order item / booking. Use PUT/PATCH to edit.

8.1 STAR BREAKDOWN PROGRESS BARS (5★ .. 1★)
--------------------------------------------------------------------------------

When calling:
  • `POST /mobileapi/product/reviews`
  • `POST /mobileapi/services/reviews`
  • `GET /mobileapi/hotels/:id` (or `/mobileapi/hotels/:id/reviews`)
  • `GET /mobileapi/food/:id`

The response now includes the `breakdown` map:
```json
"breakdown": {
  "5": 28,
  "4": 12,
  "3": 4,
  "2": 1,
  "1": 0
}
```

How to calculate percentage in Mobile UI (e.g. Flutter / React Native):
```dart
int total = data.totalRatings > 0 ? data.totalRatings : 1;
double star5Percent = (data.breakdown['5'] ?? 0) / total;
double star4Percent = (data.breakdown['4'] ?? 0) / total;
double star3Percent = (data.breakdown['3'] ?? 0) / total;
double star2Percent = (data.breakdown['2'] ?? 0) / total;
double star1Percent = (data.breakdown['1'] ?? 0) / total;
```

8.2 ORDER ITEMS: "RATE ITEM" VS "EDIT REVIEW" IN ORDER DETAILS

Endpoint: `GET /mobileapi/customer/orders/products/details/:id`

Each item in `items[]` now contains:

  "itemStatus": "DELIVERED",

if (item.review != null) {

--------------------------------------------------------------------------------
8.3 DIRECT ROUTE SHORTCUTS & ALIASES FOR MOBILE
--------------------------------------------------------------------------------

Mobile developers can now use clean, direct REST URLs without worrying about prefixing `/customer/`:

1. Hotels:
   • `GET /mobileapi/hotels/:id`  (Fetches hotel details + reviews + breakdown)
   • `GET /mobileapi/hotels/:id/reviews` (Fetches hotel customer reviews)
   • `POST /mobileapi/hotels/:id/reviews` (Submit new hotel review)

2. Food & Restaurant Dishes:
   • `GET /mobileapi/food/:id`  (Fetches dish details + reviews + breakdown)
   • `GET /mobileapi/foods/:id` (Alias for above)
   • `POST /mobileapi/customer/foods/:id/reviews` (Submit new food review)

3. Categories:
   • `GET /mobileapi/category/:id` (Alias for `/mobileapi/categories/:id`)

4. Product Browse & Search:
   • `POST /mobileapi/browse` / `GET /mobileapi/browse`
   • Products in `products[]` contain BOTH `averageRating` (double) and `reviewsCount` (int).
