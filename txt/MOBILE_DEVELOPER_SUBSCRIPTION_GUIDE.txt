1. EXECUTIVE SUMMARY: WHAT CHANGED & WHY
--------------------------------------------------------------------------------
1. Historical Price & Plan Snapshot:
   - When a seller buys or activates a plan, the server permanently stores:
     a) `paidPrice`: The exact amount paid at that moment (Number/Float).
     b) `planSnapshot`: A frozen JSON copy of the full plan details (name, price,
        duration, feature limits, quotas, etc.) at the time of purchase.
   - Even if the admin later modifies catalog plan prices or features in the Admin 
     Panel, the seller's past purchase history and invoices remain 100% accurate.

2. Free Plan 2-Month Duration (60 Days):
   - The default Free Plan is configured for 2 MONTHS (`duration: 60` days).
   - The backend automatically returns `periodStart` and `periodEnd` reflecting 
     the exact 60-day window.


--------------------------------------------------------------------------------
2. CHECKLIST OF EXACT CHANGES MOBILE DEVELOPER MUST MAKE
--------------------------------------------------------------------------------

[ ] CHANGE 1: Update Subscription & History Data Models
    - Add `paidPrice` (Number / Float) to your models.
    - Add `planSnapshot` (JSON Object / Map) to your models.

[ ] CHANGE 2: Subscription History Screen UI
    - In your Subscription History list, display `item.paidPrice ?? item.price` as the 
      historical plan price.
    - If `item.couponCode` exists, display the coupon code and discount (`item.couponDiscount`).
    - Display `item.finalPaidAmount` as the final amount charged.
    - Add a "View Plan Details" button (or Eye / Info Icon) on each history row.

[ ] CHANGE 3: Add "View Plan Details" Popup / Modal / BottomSheet
    - On every row in the Subscription History list (and on the Current Subscription card), 
      when tapped, open a modal / bottom sheet showing the details from `item.planSnapshot`.

[ ] CHANGE 4: Fallback Handling
    - If `planSnapshot` is null (for older legacy records), fallback to reading 
      from `item.plan` or `item.planName` so the app never crashes.

3. FIELD DEFINITIONS & NULLABILITY GUIDE
--------------------------------------------------------------------------------
Inside `planSnapshot`:
- `id` (String): Unique plan ID.
- `name` (String): Plan key identifier (e.g. "FREE", "BRONZE", "SILVER", "GOLD", "PLATINUM").
- `displayName` (String): User-facing plan title (e.g. "Gold Plan (Product & Service)").
- `description` (String | null): Brief plan description.
- `price` (Number): Original catalog plan price.
- `duration` (Number): Validity in days (e.g., 30 = Monthly, 60 = 2 Months, 90 = 3 Months, 365 = 1 Year).
- `maxProducts` (Number | null): Product/Service upload limit (`null` means Unlimited).
- `maxOrders` (Number | null): Order quota limit (`null` means Unlimited).
- `maxRooms` (Number | null): Hotel room limit (`null` means Unlimited).
- `features` (Object | null): Key-value pairs of included features (e.g. `{"customBadge": true, "analytics": "basic"}`).

ENDPOINT C: Purchase / Switch Plan via Mobile Checkout (with Coupons)
--------------------------------------------------------------------------------
Method: POST
Endpoint: /api/mobile/seller/subscription/checkout
Headers:
  Authorization: Bearer <SELLER_ACCESS_TOKEN>
  Content-Type: application/json

Request Payload:
{
  "planId": "plan_gold_001",
  "couponCode": "WELCOME10",
  "sellerType": "PRODUCT"
}
* Note: sellerType can be "PRODUCT", "SERVICE", "HOTEL", or "RESTAURANT"

Success Response (200 OK):
{
  "success": true,
  "message": "Subscription activated successfully",
  "subscriptionId": "sub_cm7123abc",
  "paidAmount": 1799,
  "discountAmount": 200,
  "couponCode": "WELCOME10"
}

--------------------------------------------------------------------------------
6. REGISTRATION & ONBOARDING (NO MOBILE CHANGES NEEDED)
--------------------------------------------------------------------------------
When a seller registers via mobile (`/mobileapi/.../auth/register` or social login),
the backend automatically assigns the 2-Month Free plan (`duration: 60`, `paidPrice: 0`) 
with the complete `planSnapshot`. 

The mobile app does NOT need to make any special API calls during registration; 
it works automatically out of the box.
