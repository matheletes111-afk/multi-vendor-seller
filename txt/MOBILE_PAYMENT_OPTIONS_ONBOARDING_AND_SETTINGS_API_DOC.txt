====================================================================================================
MOBILE APP DEVELOPER GUIDE: PAYMENT OPTIONS & SETTLEMENT DETAILS (BANK / ORANGE MONEY / AFRIMONEY)
FOR ALL 4 SELLER PANELS: PRODUCT SELLER, SERVICE SELLER, HOTEL SELLER, RESTAURANT SELLER
====================================================================================================
Target Audience: Flutter / React Native / iOS / Android Mobile Developers
Scope: Onboarding APIs & Profile Settings APIs across all 4 Seller Modules

----------------------------------------------------------------------------------------------------
1. OVERVIEW & UI/UX REQUIREMENT
----------------------------------------------------------------------------------------------------
In the seller onboarding flow and dashboard settings/profile update flow:
The payment / payout section has been updated to use a unified "Payment Option" dropdown / picker:

  Dropdown Values:
    1. "Bank"
    2. "Orange Money"
    3. "AfriMoney"

DYNAMIC UI BEHAVIOR:
A. When "Bank" is selected:
   - Show standard Bank details fields:
       * Bank Name (Required)
       * Account Holder Name (Required)
       * Account Number (Required)
       * BBAN Number (Required)
       * Branch Name / IFSC (Required)
       * Bank Address (Required)
       * Bank Passbook / Cheque Copy (Optional File) - field name "passbook" or "bankPassbook"
       * Bank Letter with Account No. (Optional File) - field name "bankLetter"
   - Hide Mobile Money fields.
   - The backend will automatically set "mobileNumber" and "agentNumber" to null in the database.

B. When "Orange Money" or "AfriMoney" is selected:
   - Hide ALL bank fields completely (no bank name, account number, documents, etc.).
   - Mobile Money fields:
       * Mobile Number (REQUIRED) - e.g. "076123456" or "+232 76 123456"
       * Agent Number  (OPTIONAL) - e.g. "AG-98765" or merchant code
         (Sellers can register with phone number only; agent code can be added later in settings for payout processing)
   - The backend will automatically nullify all bank fields in the database:
     (bankName, accountHolderName, accountNumber, bbanNumber, branchName, bankAddress, passbookUrl, bankLetterUrl => null).
   - The backend will automatically map:
     * preferredPayoutMethod = "Mobile Wallet"
     * mobileMoneyOption = "Orange Money" or "AfriMoney"

3. REQUEST PARAMETERS SPECIFICATION
----------------------------------------------------------------------------------------------------
Both multipart/form-data and application/json formats are supported.

+-----------------------+---------+--------------------+---------------------------------------------------+
| Parameter Name        | Type    | Applicable When    | Description / Rules                               |
+-----------------------+---------+--------------------+---------------------------------------------------+
| paymentOption         | string  | ALWAYS (REQUIRED)  | "Bank", "Orange Money", or "AfriMoney"            |
+-----------------------+---------+--------------------+---------------------------------------------------+
| mobileNumber          | string  | Orange / AfriMoney | REQUIRED for mobile money. Registered phone no.   |
| agentNumber           | string  | Orange / AfriMoney | OPTIONAL for mobile money. Merchant / Agent code  |
+-----------------------+---------+--------------------+---------------------------------------------------+
| bankName              | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| accountHolderName     | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| accountNumber         | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| bbanNumber            | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| branchName            | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| bankAddress           | string  | Bank Only          | REQUIRED when paymentOption == "Bank"             |
| passbook              | File    | Bank Only          | OPTIONAL image/pdf proof (or key: bankPassbook)   |
| bankLetter            | File    | Bank Only          | OPTIONAL image/pdf bank letter with account no.   |
+-----------------------+---------+--------------------+---------------------------------------------------+
| section               | string  | Both Onboarding &  | "bank" (or "business", "kyc", "store",            |
|                       |         | Settings           |  "property", "restaurant", "agreement")           |
| step / mobileStep     | string  | Onboarding Only    | Auto-detected; accepts 1-based or 2-based numbers |
+-----------------------+---------+--------------------+---------------------------------------------------+

BACKWARD COMPATIBILITY NOTE:
If an older mobile build sends "preferredPayoutMethod": "Mobile Wallet" with "mobileMoneyOption": "Orange Money",
the server will automatically normalize it to paymentOption = "Orange Money" so older versions won't break.

6. VALIDATION & ERROR RESPONSES
----------------------------------------------------------------------------------------------------

1) Missing mobileNumber when Orange Money or AfriMoney is selected:
   Status: 400 Bad Request
   { "success": false, "error": "Mobile Number is required for Orange Money." }
   { "success": false, "error": "Mobile Number is required for AfriMoney." }

   NOTE: agentNumber is OPTIONAL. Submissions without agentNumber will succeed.
   Sellers can register with phone number only and add their agent code later for payouts.

2) Missing Bank fields when Bank is selected:
   Status: 400 Bad Request
   { "success": false, "error": "Bank Name is required." }
   { "success": false, "error": "Account Holder Name is required." }
   { "success": false, "error": "Account Number is required." }
   { "success": false, "error": "BBAN Number is required." }
   { "success": false, "error": "Branch Name is required." }
   { "success": false, "error": "Bank Address is required." }

NOTE: Error responses from the API are returned with "success": false and "error" key.
      These errors are only triggered when SUBMITTING data (onboarding/settings update).
      GET (pre-fetch) requests do not trigger validation errors.

7. STEP MAPPING & AVOIDING STEP MISMATCH ERRORS (IMPORTANT FOR MOBILE APPS)
----------------------------------------------------------------------------------------------------
In previous versions, discrepancies between 1-based indexing (mobile UI steps 1..5) and 2-based 
database steps (steps 2..6) could cause validation errors from one step to leak into another.

THE BACKEND HAS BEEN FULLY UPGRADED WITH MULTI-LAYER SAFETY:
1. Auto-Detection by Payload Signature:
   Regardless of what step number is sent, if your payload contains payment fields (paymentOption, 
   mobileNumber, bankName, etc.), the backend ALWAYS routes to the Bank step!

2. Explicit Section Name (RECOMMENDED):
   You can now include `section` (or `stepName`) in your request:
   - "business"   -> Business Information (Step 1)
   - "kyc"        -> Identity Verification / KYC (Step 2)
   - "store"      -> Store Setup (Product)
   - "service"    -> Service Setup (Service)
   - "property"   -> Property Setup (Hotel)
   - "restaurant" -> Restaurant Setup (Restaurant)
   - "bank"       -> Bank & Mobile Money Details
   - "agreement"  -> Legal Agreement (Final Step)

3. Consistent Step Numbers in All GET Responses:
   - GET /mobileapi/product-seller/onboarding
   - GET /mobileapi/service-seller/onboarding
   - GET /mobileapi/hotel-seller/onboarding
   - GET /mobileapi/restaurant-seller/onboarding

   All 4 GET endpoints return:
   - `mobileStep`: 1 to 5 (Consistent 1-based step for mobile UI)
   - `currentStep`: 1 to 5 (Consistent 1-based step for mobile UI)
   - `step`: 2 to 6 (Database step number)
   - `section`: "business" | "kyc" | "store" | "property" | "restaurant" | "bank" | "agreement"
   - `stepName`: Identical to section
