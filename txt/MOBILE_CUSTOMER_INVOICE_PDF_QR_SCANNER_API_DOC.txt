1. OVERVIEW & WHAT CHANGED
--------------------------------------------------------------------------------
This guide covers all backend APIs and UI rules for:
  1. Customer Tax Invoice JSON API (multi-vendor & single-vendor orders)
  2. Real A4 PDF Invoice Download API (Bearer token OR signed 15-min URL)
  3. Invoice QR Code & QR Scanner Verification APIs
  4. Customer Order List & Order Detail updates (Delivery Region/Zone + Invoice URLs)
  5. Mandatory Customer UI rule: Hide internal delivery fee price breakup
  6. Mobile Media/Image URL Normalization for Restaurants, Foods, Hotels, Ads,
     Banners, Cart, Wishlist, Exchange Options, Bookings, Orders & Reviews (Section 9)
  7. Restaurant Cuisines, Hotel/Food Location Formatting & Seller Write/Read
     Normalization Updates (Section 10)

ALL EXISTING ENDPOINTS REMAIN 100% BACKWARD-COMPATIBLE.
Currency: NLe (Sierra Leonean Leone), formatted as: NLe X,XXX.XX

--------------------------------------------------------------------------------
2. AUTHENTICATION
--------------------------------------------------------------------------------
All customer endpoints accept:
  Authorization: Bearer <customer_access_token>

Exception for in-browser / WebView PDF download (`GET .../invoice/pdf`):
  Pass `?dlToken=<signed_15min_token>` (returned automatically as `signedPdfUrl`
  by the Invoice JSON and QR Scan APIs) when launching an external PDF viewer or
  `url_launcher` that cannot attach custom Authorization headers.

5. DOWNLOAD A4 INVOICE PDF
--------------------------------------------------------------------------------
Endpoint:
  GET /mobileapi/customer/orders/[id]/invoice/pdf

Query Parameters:
  - sellerId=<optional>      (single merchant PDF; omit for all merchants)
  - disposition=attachment|inline  (default: attachment)
  - dlToken=<optional>       (15-min signed token when Bearer header isn't used)

Authentication Options:
  Option A (Recommended for in-app file download + share/preview):
    Header -> Authorization: Bearer <customer_access_token>
  Option B (Recommended for external browser / `url_launcher` without headers):
    Query  -> ?dlToken=<signedPdfUrl's dlToken> (already embedded in `signedPdfUrl`)

Response (200 OK):
  Content-Type: application/pdf
  Content-Disposition: attachment; filename="MEEEM-Invoice-<orderNumber>.pdf"
  Cache-Control: no-store
  Body: Raw A4 vector PDF binary bytes (multi-page if multi-seller or many items;
        includes embedded vector QR code, delivery charge, delivery region/zone,
        items, GST, coupon discount, payment ref, and declarations).

Error Responses:
  - 401 Unauthorized / Invalid or expired download token
  - 403 Forbidden
  - 404 Not Found

6. INVOICE QR SCANNER & VERIFICATION APIS
--------------------------------------------------------------------------------
There are TWO endpoints for scanning/verifying invoice QR codes:

6A. Customer App QR Scanner Endpoint (Authenticated Customer)
  POST /mobileapi/customer/orders/invoice/scan-qr
  GET  /mobileapi/customer/orders/invoice/scan-qr?qr=<scanned_string>

  Headers:
    Authorization: Bearer <customer_access_token>
    Content-Type: application/json (for POST)

  POST Request Body:
  {
    "qrData": "<raw string scanned from camera>"
  }
  (Also accepts `qr`, `token`, `t`, `code`, or `orderNumber` keys.)

  Supported Scanned Formats (Backend parses all automatically):
    1. Signed QR URL:    "https://meeemsl.com/invoice/verify?t=M1...."
    2. Raw Signed Token: "M1.eyJvIjoi..."
    3. JSON QR Payload:  "{\"token\":\"M1...\"}" or "{\"orderNumber\":\"meeem00000012\"}"
    4. Legacy QR Text:   "Order: #meeem00000012 | Store: ..."
    5. Order / Inv Ref:  "INV-REF-meeem00000012-XPRO", "INV-meeem00000012",
                         "#meeem00000012", "meeem00000012"

  Success Response (200 OK):
  {
    "success": true,
    "verified": true,
    "message": "Invoice QR verified successfully",
    "data": {
      "verificationMode": "SIGNED_TOKEN",
      "isPublicMasked": false,
      "isOwner": true,
      "orderId": "cm4x...",
      "orderNumber": "meeem00000012",
      "invoiceCount": 1,
      "pdfDownloadUrl": "/mobileapi/customer/orders/cm4x.../invoice/pdf",
      "signedPdfUrl": "https://meeemsl.com/mobileapi/customer/orders/cm4x.../invoice/pdf?dlToken=P1...",
      "invoice": { ...InvoiceData... },
      "invoices": [ ...InvoiceData[]... ]
    }
  }

  Privacy Behavior:
    - If the scanned signed `M1.` QR belongs to the authenticated customer (`isOwner = true`),
      `isPublicMasked` is `false` and full customer/address/PDF download links are returned.
    - If the scanned signed `M1.` QR belongs to another user's order (`isOwner = false`),
      `isPublicMasked` is `true`: phone/email/street-line PII are masked, while order items,
      delivery charge, delivery region/zone, store, totals, and verification status are returned.
    - Unsigned plain `orderNumber` / legacy strings are ONLY allowed when `isOwner = true`
      (otherwise 403 Forbidden).

6B. Universal QR Verify Endpoint (Signed-in OR Public Signed-Token Scan)
  POST /mobileapi/invoice/verify
  GET  /mobileapi/invoice/verify?t=<token_or_qr_string>

  Headers:
    Authorization: Bearer <token>   (Optional if scanning signed `M1.` QR;
                                     Required for unsigned orderNumber lookup)

  Response Shape:
    Matches Section 6A: `{ success, verified, message, data: { verificationMode, isPublicMasked, isOwner, orderId, orderNumber, invoiceCount, pdfDownloadUrl, signedPdfUrl, invoice, invoices } }`.
    When `isOwner === true`, both `data` and each element of `invoices[]` include mobile
    `pdfDownloadUrl` (`/mobileapi/customer/orders/[id]/invoice/pdf...`) and a 15-min
    seller-scoped `signedPdfUrl`. When `isOwner === false` (`isPublicMasked === true`),
    `pdfDownloadUrl` and `signedPdfUrl` are omitted/`null`.

7.2 Fetch Invoice JSON & Download A4 PDF
----------------------------------------
  import 'dart:convert';
  import 'dart:io';
  import 'package:http/http.dart' as http;
  import 'package:path_provider/path_provider.dart';
  import 'package:open_filex/open_filex.dart';

  class CustomerInvoiceService {
    final String baseUrl;
    final String accessToken;

    CustomerInvoiceService({required this.baseUrl, required this.accessToken});

    Map<String, String> get _headers => {
          'Authorization': 'Bearer $accessToken',
          'Content-Type': 'application/json',
        };

    Future<Map<String, dynamic>> fetchOrderInvoice(
      String orderId, {
      String? sellerId,
    }) async {
      final query = sellerId != null ? '?sellerId=$sellerId' : '';
      final uri = Uri.parse('$baseUrl/mobileapi/customer/orders/$orderId/invoice$query');
      final res = await http.get(uri, headers: _headers);
      final body = jsonDecode(res.body) as Map<String, dynamic>;
      if (res.statusCode != 200 || body['success'] != true) {
        throw Exception(body['error'] ?? 'Failed to load invoice');
      }
      return body['data'] as Map<String, dynamic>;
    }

    Future<File> downloadAndOpenInvoicePdf(
      String orderId,
      String orderNumber, {
      String? sellerId,
    }) async {
      final query = sellerId != null ? '?sellerId=$sellerId' : '';
      final uri = Uri.parse('$baseUrl/mobileapi/customer/orders/$orderId/invoice/pdf$query');
      final res = await http.get(uri, headers: {
        'Authorization': 'Bearer $accessToken',
      });
      if (res.statusCode != 200) {
        throw Exception('PDF download failed (${res.statusCode})');
      }

      final dir = await getTemporaryDirectory();
      final file = File('${dir.path}/MEEEM-Invoice-$orderNumber.pdf');
      await file.writeAsBytes(res.bodyBytes, flush: true);
      await OpenFilex.open(file.path);
      return file;
    }

    Future<Map<String, dynamic>> scanInvoiceQr(String rawQrValue) async {
      final uri = Uri.parse('$baseUrl/mobileapi/customer/orders/invoice/scan-qr');
      final res = await http.post(
        uri,
        headers: _headers,
        body: jsonEncode({'qrData': rawQrValue}),
      );
      final body = jsonDecode(res.body) as Map<String, dynamic>;
      if (res.statusCode != 200 || body['verified'] != true) {
        throw Exception(body['error'] ?? 'Invalid or unreadable invoice QR');
      }
      return body['data'] as Map<String, dynamic>;
    }
  }

7.3 Rendering Base64 QR Image (`qrDataUrl`) in Flutter
------------------------------------------------------
  // Strip "data:image/png;base64," prefix and decode bytes:
  Widget buildQrImage(String qrDataUrl) {
    final base64Str = qrDataUrl.contains(',')
        ? qrDataUrl.split(',').last
        : qrDataUrl;
    final bytes = base64Decode(base64Str);
    return Image.memory(bytes, width: 110, height: 110, fit: BoxFit.contain);
  }

9. RESTAURANT, FOOD, HOTEL, AD & CATALOG MEDIA / IMAGE URL FIXES
--------------------------------------------------------------------------------

9.1 Root Cause & Backend Media Proxy Behavior
---------------------------------------------
Previously, images uploaded under restricted S3 folders
  - `uploads/restaurant-onboarding/property/*` (Restaurant logo, banner, mainPhoto)
  - `uploads/hotel-onboarding/property/*`      (Hotel seller logo, banner, mainPhoto)
  - `uploads/onboarding/store/*`               (Store logos)
  - `uploads/return-images/*`                  (Customer return photos — now also whitelisted on `/api/media/...`)
returned `403 Forbidden` when requested directly from S3, or received internal
`http://localhost:3000/...` proxy origins behind reverse proxies, or returned raw
JSON-stringified image arrays (`"[\"https://...\"]"`) / relative `/uploads/...`
or `/icons/...` paths on mobile endpoints.

ALL customer-facing mobile APIs now automatically:
  1. Resolve the public HTTPS origin from `x-forwarded-host` / `x-forwarded-proto`
     headers (falling back to `NEXT_PUBLIC_APP_URL` / `NEXTAUTH_URL`).
  2. Rewrite restricted S3 property/store image URLs into full public HTTPS URLs:
       `https://<public-domain>/api/media/uploads/<key>`
     The `/api/media/[...path]` endpoint is PUBLIC (no Bearer header required)
     and includes `Access-Control-Allow-Origin: *`.
  3. Convert relative asset/upload paths (`/uploads/...`, `/icons/...`) and bare
     S3 keys (`uploads/...`) to full `https://...` URLs.
  4. Parse JSON-encoded image strings & arrays cleanly into clean string URLs and
     encode spaces cleanly (`%20`).

9.5 Mobile Image Loading Guidance (Flutter / React Native)
----------------------------------------------------------
  - Use `image_url` (or `coverImage` / `banner` / `mainPhoto` / `logo` / `images[0]`)
    directly in `Image.network` / `CachedNetworkImage`.
  - No `Authorization` header is needed to load `/api/media/...` URLs.
  - Because `restaurant_logo` / `restaurant_banner` / `hotel_banner` are now also
    returned as full HTTPS URLs alongside `image_url`, mobile UI cards can render both
    dish/hotel photos and seller/restaurant avatars cleanly without local URL rewriting.

10. RESTAURANT CUISINES & LOCATION FORMATTING UPDATES
--------------------------------------------------------------------------------
  - `GET /mobileapi/restaurants` & `GET /mobileapi/restaurants/[id]`
    (plus aliases `/mobileapi/restaurant/[id]`, `/mobileapi/restaurant/seller/[id]`):
      * Recursively unwraps any multi-encoded / CSV `primaryCuisine` strings into a
        clean deduplicated `cuisines[]` string array and comma-joined `cuisine_type`.
      * Formats `street`, `city`, `state`, and `landmark` (spacing, punctuation,
        Title Case normalization) and returns deduplicated `locationText` and
        `location_text` (falling back to `"Local"` when empty).
  - `GET /mobileapi/v1/restaurants/nearby`:
      * Uses `businessInfo.businessName` before `user.name`, merges `primaryCuisine` +
        food item categories into clean `cuisines[]` & `cuisine_type`, and returns
        formatted `city`, `street`, and `location_text` (with `"Local"` fallback).
  - `GET /mobileapi/customer/foods`, `GET /mobileapi/v1/foods` & `GET /mobileapi/foods/categories`:
      * `restaurantCity` and food cuisine/category labels are cleaned via
        `formatLocationPart` and `parseCleanStringArray`.
  - `GET /mobileapi/v1/categories/hotels`, `GET /mobileapi/v1/hotels*`,
    `GET /mobileapi/v1/deals/hotels` & `GET /mobileapi/v1/recommendations/hotels`:
      * Hotel `city`, `address`, and `location_text` are formatted via
        `formatLocationPart` / `formatRestaurantLocation` (with `"Local"` fallback
        instead of hardcoded Dubai/Downtown defaults on real DB records).
  - Restaurant Seller App Endpoints (`POST /mobileapi/restaurant-seller/onboarding`,
    `GET|PUT /mobileapi/restaurant-seller/settings`, `GET /mobileapi/restaurant-seller/onboarding`):
      * Write paths normalize incoming `cuisines` and `services` via
        `parseCleanStringArray` before saving; `GET` endpoints return clean arrays /
        normalized JSON strings and presigned onboarding media URLs.
